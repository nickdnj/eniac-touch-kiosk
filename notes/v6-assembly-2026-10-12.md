## How the timeline re-times itself (no hard-coded seconds)
1. **Line positions.** Clip with exactly one audio stream: each per-line WAV is cross-correlated into it (score must be >= 0.9, as v5).
   Video-only clip: `<clip>-timeline.json` (`at` ms, from the kiosk narrate.ts) shifted by the logged cuts + `v6_mux_cuts.json`.
   The raw-webm length minus all cuts must equal the clip length (checked; mismatch = the cuts file is wrong).
2. **Baked units** (B, B2, D, E, G, I, N, O): window = line anchor + the offset v5 used, frame-aligned. Each anchor is
   `(line, start|end, offset)`, offsets measured from `output/build/v5-line-positions.json`; table `ANCH` in the generator, stored in the JSON as `cut_anchors`.
   An edge that would land inside a spoken word is pushed past it and reported (`PUSHED`); a hand-cut jump inside a window is a hard error;
   a window past the clip end is a hard error. Unit duration is simply `out - in`.
3. **Standalone-line units** (A, H, J, K, L, M, O, P): `duration = lead-in + probed line duration + the SAME tail slack v5 had after that line`
   (P: v5b's 1.79 s). Audio is never sped up and never cut; only silence is added or removed.
4. Everything downstream (crossfades, music cues, overlays that ride a line, chapter times, cutaway photos) derives from those durations.
   Line-synchronous overlays follow their line: A chapter-1 lower third scales with N01, E/G cutaway photos hang off tour-16 / the word gap
   after the six names (silencedetect in tour-27), the vcfed.org reveal and the bed's post-voice cue come from N06's alignment JSON.

## Risks
1. **Cut anchors assume the same action-to-narration spacing as v5.** Offsets were measured on v5 and are applied to new takes. The dry run looked right,
   but the final clips need the same edge check: `output/build/v6/units/*.mp4`, first/last frame of each baked unit (B, B2, D, E, G, I, N, O; K ends on "Landed").
2. **Take pacing vs. new WAV lengths.** A baked line longer than the gap it was paced for overlaps the next one; assemble stops on any voice overlap > 0.02 s and the
   generator logs `PUSHED` edges. Many v6 kiosk lines are +-1-2.7 s from v5 for identical text (TTS variance), so M1's re-pace must use the NEW WAV durations.
3. **Hand cuts are not portable** (M1 note #3: flight speed differs run to run). `v6_mux_cuts.json` must match the final mux commands or the cut-sum check FAILS.
4. **K window** is anchored to trajectory-12 ("Landed") minus 5.78 s, clamped after the last hand-cut jump; if the final trajectory has a jump
   closer than that to the landing, K starts right after the jump (shorter lead-in). Assert stops it running into the summary screen.
5. **Honor-roll cutaway (P3)** hangs off the pause after the sixth name, found by silencedetect near the character-fraction of "Lichterman." Verify by ear/eye
   (v6 tour-27 is 15.74 s vs 17.51 s in v5 and the pauses are shorter).
6. **True peak sits at the limit**: the program master is -2.4 dBTP; the -1.5 dBTP reading is the VCF intro audio (loudnormed to TP -1.5, as in v5) plus AAC. Preflight passes
   at <= -1.5 but with no margin; lowering the intro's TP target to -2.0 in `prep_intro` would give margin (not done: it changes the intro audio).
7. Post-voice bed level on the close card is -7 dB (v5's value after N06); v5b's exact tail cue is not recorded, so the ending may differ slightly from v5b.
8. `lamps` check wants a verify image NEWER than each clip and none named *WRONG*/*FAIL* newer than it. `original-ui-tour` has no image in `_verify/` yet.
9. Dry-run inputs live in M1-owned dirs (`takes-silent`, `video-v5/.../narration`); the dry run is reproducible only while they stay.
